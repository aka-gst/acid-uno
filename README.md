# ACID UNO

Мобильная UNO с физичным drag-and-drop и neon/cyberpunk UI.

## Быстрый запуск

Игра — статика, ей достаточно любого файлового сервера:

```sh
python3 -m http.server 4173
```

Для игры по ссылке нужен сервер комнат. Он же отдаёт и статику,
поэтому в бою запускают только его:

```sh
node server/server.js
```

Открыть: `http://127.0.0.1:4173/`. Порт меняется через `PORT`.

## Игра по ссылке

В лобби кнопка «СЫГРАТЬ ПО ССЫЛКЕ» создаёт комнату и показывает
четырёхбуквенный код и ссылку.

В комнате:

- «+ БОТ» сажает бота на свободное место, «− БОТ» убирает последнего;
- «НАЧАТЬ СЕЙЧАС» раздаёт, не дожидаясь остальных — пустые места
  просто убираются, стол сжимается до тех, кто пришёл;
- если все места заняли, партия начинается сама.

Боты в комнате ходят на сервере той же политикой, что и в одиночной
игре (`src/bot.js`), и объявляют UNO с задержкой — чтобы их можно было
поймать на молчании.

Правду считает сервер тем же `src/match.js`, что и клиент:

- ходить за соседа нельзя — место берётся из токена, а не из тела
  запроса;
- чужие руки клиенту не отправляются, только количество карт;
- часы идут на сервере, клиент их только рисует;
- перезагрузка страницы возвращает на своё место — токен лежит
  в `sessionStorage`.

Обмен идёт обычным HTTP: действия уходят `POST`-ом, состояние
возвращается потоком `text/event-stream`. Зависимостей нет.

### На своём сервере

Развёрнуто на `aka-gst.ru/acid/`: статику отдаёт Caddy из каталога
сайта, комнаты — отдельный контейнер. Рецепт лежит в `deploy/`:

- `deploy/docker-compose.yml` — контейнер `acid-uno` из голого
  `node:24-alpine`. Зависимостей нет, собирать нечего: исходники
  монтируются на чтение. На сервер едут только `server/` и `src/`.
- `deploy/caddy-route.txt` — маршрут для Caddy.

Через любой прокси обязательно отключить буферизацию, иначе поток
состояния встанет и стол у игроков замрёт без единой ошибки в журнале:
`flush_interval -1` у Caddy, `proxy_buffering off` у nginx.

Комнаты живут в памяти процесса: перезапуск сервера обрывает
незаконченные партии — клиент в этом случае говорит «связь с комнатой
потеряна», а не молчит. Комната, из которой ушли все живые игроки,
убирается через пять минут (`ROOM_TTL_MS` в `server/rooms.js`).

Живость сервиса — `GET /api/health`.

## Тесты

Зависимостей нет, нужен только Node 18+.

```sh
node --test "test/*.test.js"
```

Отдельно — прогон партий бот-против-бота (баланс, длительность,
поведение таймера):

```sh
node test/simulate.js 4000 4 1
```

Аргументы: число партий, число мест, число живых игроков, лимит в
секундах. Лимит по умолчанию берётся из `AcidRules.matchLimitFor()`;
чтобы измерить чистую длительность, передай заведомо большой,
например `999999`.

## Где что менять

Правила игры живут в одном месте. Всё остальное — состояние партии,
отрисовка и анимации.

- `src/rules.js` — **правила**: колода, ходимость, кластер `+2/+4`,
  перехват, сортировка руки, очки, кольцо мест и направление хода,
  часы партии, машина состояний UNO, выбор карты ботом. Ни DOM, ни
  таймеров — модуль работает и в браузере, и в Node.
- `src/match.js` — **партия как чистый редьюсер**:
  `apply(state, action) -> { state, events, error }`. Случайность
  живёт в самом состоянии отдельным числом, поэтому одна и та же
  последовательность действий всегда даёт одну и ту же партию.
  `view(state, seat)` отдаёт наружу состояние без чужих рук.
  На этом же редьюсере будет считать сервер.
- `src/store.js` — **единственное место, где состояние меняется**.
  `AcidStore.dispatch(action)` отправляет действие через транспорт и
  проецирует новое состояние в переменные `game.js`, которые читает
  отрисовка. Отклонённое действие не меняет ничего. `subscribe()`
  отдаёт события хода — по ним играет звук и анимации в комнате.
- `src/transport.js` — куда уходит действие: в локальный редьюсер
  или на сервер комнаты. Оба отвечают одинаково, поэтому подмена
  одного другим ничего не меняет ни в отрисовке, ни в управлении.
- `src/bot.js` — политика бота: чем ходить и когда объявлять UNO.
  Одна на всех — одиночная игра, комната и симулятор баланса. Если бы
  их было три, замеры длительности партии перестали бы относиться
  к настоящей игре.
- `src/room.js` — создание комнаты, ссылка, состав стола.
- `server/server.js` — статика и API комнат в одном процессе.
- `server/rooms.js` — комнаты: места, токены, рассылка состояния,
  серверные часы.
- `src/audio.js` — звук. Синтезируется на WebAudio, файлов нет.
- `src/tutorial.js` — экран правил. Карты в нём рисуются тем же
  `cardHTML()`, что и карты в руке, поэтому объяснение не расходится
  с игрой. Открывается из лобби и один раз сам, при первом запуске.
- `src/features.js` — слой поверх игры: лобби, аура активного цвета,
  крупный счётчик кластера, часы партии, звуковые события. Оборачивает
  существующие глобальные функции, ничего не переписывая.
- `game.js` — проекция состояния и базовая отрисовка. Часто меняемые
  пороги UI — в `ACID_UI`. Колоды, тасовки и правил здесь больше нет:
  всё это в `src/match.js` и `src/rules.js`.
- `v9.1.js` — взаимодействие: drag, добор, UNO, ход бота, анимации
  хода. Ничего не мутирует — только шлёт действия в `AcidStore`
  и рисует по событиям, которые тот вернул.
- `animations.js` и `effects.css` — переиспользуемые игровые эффекты.
- `index.html` — только структура экрана и подключения.
- `style.css` — базовый дизайн. Цвета, размеры карт и главные параметры
  находятся в блоке `ACID UNO — EDITABLE DESIGN TOKENS` в самом начале.
- `v9.1.css` — состояния движения, UNO, веер бота и адаптивные
  portrait/landscape-режимы.
- `features.css` — аура, счётчик кластера, таймер, итог по очкам.

## Как это связано

```
src/rules.js      чистые правила
src/match.js      apply(state, action) -> { state, events }
src/transport.js  локально или в комнату
src/store.js      dispatch() -> проекция состояния
game.js           отрисовка читает проекцию
v9.1.js           взаимодействие шлёт действия
```

Никто, кроме `src/store.js`, не присваивает значения переменным
партии. Поэтому одиночная игра и комната — это один и тот же код
с разным транспортом; `server/` берёт `src/match.js` как есть.

## Правила

- Классические 108 карт.
- Кластер штрафов: `+2` кроется `+2` или `+4`, `+4` — только `+4`.
  Принять штраф — значит закончить свой ход.
- Стол от 2 до 7 мест. Место 0 живое, остальные — боты.
- Пропуск и разворот в игре на двоих оставляют ход тому же игроку.
  От трёх мест пропуск перешагивает соседа, а разворот меняет
  направление.
- Перехват: карту, полностью совпадающую с верхней, можно выложить
  вне очереди.
- UNO объявляется, когда в руке ровно две карты. Любой рост руки
  снимает объявление.

### Таймер и очки

Партия ограничена по времени. Лимит не берётся из таблицы, а считается
из физики стола:

```
лимит = ходов до конца партии × средняя цена одного хода
```

Первый множитель зависит от числа мест, второй — от доли живых мест:
живой игрок обдумывает ход руками, бот разыгрывает его мгновенно.
Поэтому лимит растёт от 3:50 на двоих против бота до 12:10 на семерых
живых. Все числа сняты с `test/simulate.js`, худшая ошибка модели на
сетке 2..7 мест × 1..7 живых — 0.9%.

Лимит подобран так, чтобы по очкам доигрывалось около 16% партий на
любом столе. Без часов кластер `+2/+4` на больших столах разгоняется:
на семерых 45% партий видят кластер `+8` и больше, а хвост
длительности уходит за два часа. Часы — то, что делает стол на 5–7
мест играбельным.

За минуту до конца таймер выходит на экран.

По гонгу выигрывает тот, у кого меньше сумма карт:

- числовые — по номиналу;
- `+2`, разворот, пропуск, смена цвета — по 20;
- `+4` — 40.

Кластер, висящий на столе в момент гонга, сначала уходит тому, кто
обязан был его забрать: иначе `+4` на последней секунде выигрывал бы
партию бесплатно.

Часы выключаются в лобби галочкой «ИГРАТЬ БЕЗ ТАЙМЕРА» — это и есть
единогласное решение живых игроков, пока живой игрок один. Программно:
`AcidClock.disableClock()`.

## Карты и адаптивность

- Базовый размер карты задаётся через `--card-w` и `--card-h` в `style.css`.
- Desktop-размеры находятся в media-блоке `DESKTOP / LARGE TABLET`.
- При 14+ картах рука получает класс `is-crowded`, и на картах появляются постоянные угловые индексы. Порог задаётся в `ACID_UI.crowdedHandAt`.
- Карты бота используют те же `--card-w` и `--card-h`, что и карты игрока; плотность веера вычисляется в `getBotFanLayout91()`.
- Разлёт руки ограничивает `getFanLayout()` в `game.js`. Карта вращается
  вокруг середины нижней кромки (`transform-origin: 50% 100%` в
  `v9.1.css`), поэтому по горизонтали занимает заметно больше своей
  ширины — считать по `--card-w` значит срезать крайние карты.
- Рука всегда отсортирована: чёрные карты отдельной группой слева,
  дальше цвета, внутри цвета — по возрастанию номинала.

После правок проверять минимум три viewport: `390×844`, `844×390`, `1440×900`.
